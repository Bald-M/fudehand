# macOS Usage Guide

Fudehand is a native SwiftUI/AppKit design tool. The canvas renders the layers of the design document directly with Core Animation and does not depend on a web server (see [ADR 0006](adr/0006-native-design-document.md)).

## Launching and Building

Requires macOS 14+, Swift 6+, Node.js 22.12+, and pnpm 11.7.0. Installing the Xcode Command Line Tools is enough; full Xcode is not needed, and there are no third-party Swift package dependencies.

```bash
pnpm install
pnpm dev                 # Debug build, then open the App
pnpm build:native        # Release build with local ad-hoc signing
open dist/Fudehand.app
```

When the App starts it first shows the launch window and starts no Node processes:

- On the left, New Design Document (新建设计文档, ⌘N) opens a blank untitled document, and Open… (打开…, ⌘O) shows the open panel.
- Recent (最近打开) lists recently opened or saved project files in reverse chronological order (up to 10), showing the file name, its folder, and the time. Click an item, or select it and press Return, to open it; files that were deleted or moved are shown as unavailable, and clicking one shows a notice and offers to remove it from the list; Clear Recents (清除记录) empties the list.
- Templates (模板) lists the templates bundled with the App, and shows No Templates (暂无模板) when there are none. Clicking a template gives an untitled document that is not linked to the template file; saving asks for a location.

Once editing starts — via New, Open, a recent item, a template, opening a file from Finder, or the Agent's `new_document` / `open_document` / `open_recent` / `new_document_from_template` — the editor window opens and the launch window closes; Window › Launch Window (窗口 › 启动窗口), or the Agent's `show_launch_window`, reopens it. The editor window is not restored on quit, so the next launch shows the launch window first again. The Agent harness starts only when the chat panel sends its first message.

**UI language.** The App comes in US English, British English, Simplified Chinese, and Traditional Chinese. The first launch uses US English whatever the system language is. The app menu's Language submenu switches language: every window and the App's own menu items change immediately, the choice is saved and used at the next launch, and the system-provided menu items (About, Quit, Hide, the standard Edit and Window items) change at the next launch, as the submenu notes. Switching never changes a design document: layer names stay as they are. A layer without a name — newly created, or read from a project file that omits `name` — gets its default name in the language in use at that moment. Project-file errors (not a project file, missing or newer format version) follow the UI language wherever they are shown, including the Agent's `open_document`, `open_recent`, and `new_document_from_template`; the control channel's other errors (protocol, field validation, commands) are not localized.

Templates live in `native/Resources/Templates/`: put a `.fudehand` file there and rebuild, and it appears in the Templates section with no code changes, though `BundledTemplateTests` then asks for a string-table entry and the design foundations (see the README there). The file name (US English) is the template's name and its key in the string tables, so the bundled templates show in the UI language; a template without a table entry shows its file name. The bundled starter templates (Mobile App, Web Page, Dashboard) follow [Design foundations](design-foundations.md).

The build script writes the local source directory, the Node path, and the PATH at launch time into the App's `Contents/Resources/workspace.json`; the chat panel uses it to find `scripts/agent-chat.mjs` and Node. The canvas, layers, and project files do not depend on the source directory; if the App is copied to another machine, only the chat panel stops working.

SwiftPM build output and the module cache go to the system temporary directory by default. `FUDEHAND_SWIFT_SCRATCH` overrides the build directory, and `FUDEHAND_SWIFT_MODULE_CACHE` overrides the module cache directory. Do not run two Swift builds in the same scratch directory at the same time.

## Files

- File menu (文件): New ⌘N, Open ⌘O, Open Recent (打开最近), Save ⌘S, Save As ⇧⌘S, Export as HTML… ⇧⌘E. Export as HTML writes the selected layer (exactly one; also in the layers panel's context menu) as `index.html` with its images and icons under `assets/`, into a folder chosen in an open panel that can create folders; the folder must be empty, so an export never replaces files, and the document is not changed. Auto layout becomes flexbox, other children are placed absolutely, icons are drawn through a CSS mask in the icon color (SF Symbols as 256 × 256 PNG, other icons as SVG), and hidden layers and prototype settings are left out. Open Recent shares one record with the launch window's Recent list (written on every successful open or save, deduplicated, moved to the top, up to 10 items), and the record can be cleared at the end of the submenu. Project files use the `.fudehand` extension and contain versioned JSON (see the [design spec](superpowers/specs/2026-11-17-native-design-document-design.md#document-format-fudehandcoredesigndocumentswift) for the format).
- With unsaved changes, the window title shows Edited (已编辑); New, Open, or quitting first asks whether to save.
- Opening a malformed file, or one created by a newer version, shows the specific reason and leaves the current document unchanged.
- The App exports the `.fudehand` file type in Info.plist (`local.fudehand.design`, conforming to JSON) and registers itself as its editor: after building, double-clicking in Finder, dragging onto the Dock icon, or Open With all open project files in Fudehand. The App edits one document at a time, so opening a file replaces the current document (asking first if there are unsaved changes).

## Canvas Interaction

Interaction follows Figma.

**Selection**

- Clicking content inside a top-level frame selects its direct child layer; clicking empty space in the frame, or the name label above the frame, selects the frame; clicking any other top-level layer selects it directly.
- When a layer is selected, clicking one of its siblings selects that sibling directly; double-clicking the selected layer selects the next child layer under the pointer; ⌘ + click selects the deepest layer directly.
- A group can only be hit through its child layers, and clicking selects the whole group. Locked or hidden layers cannot be hit on the canvas and can only be selected in the layers panel.
- Shift + click adds to or removes from the selection; dragging on empty canvas does a marquee selection of top-level layers, and Shift adds to it. Hovering shows a thin outline.
- Esc selects the parent layer, or clears the selection at the top level; Return selects the children of the selected frame or group; ⌘A selects all layers at the current level.

**Moving and Resizing**

- Drag selected layers to move them (starting after a 3pt threshold); with multiple layers selected they move together. One drag is one undo step. The position of a child layer in an auto layout frame is determined by the layout and does not follow the drag.
- While dragging, layer edges and center lines snap when within 6 screen points of a sibling layer, the parent frame, or an edge of the visible layout guide columns and rows of the nearest enclosing frame (past any groups), and red guides appear; hold ⌃ while dragging to turn snapping off. Dragging a resize handle snaps the edges it moves to the same targets, and ⌃ turns that off too.
- With a single selection (except groups), 8 resize handles appear; dragging one changes the size and sets the sizing mode in that direction to fixed. For text, changing the width switches it to Auto Height (自动高度), and changing the height switches it to Fixed (固定).
- Arrow keys move by 1 and Shift + arrow keys by 10, each key press being one undo step. Delete removes the selected layers.

**Layout Guides**

- A frame can hold any number of layout guides, drawn in the order they were added: a **grid** (lines every *size* points across the frame), **columns**, or **rows**. Columns and rows have a count, an alignment, a gutter between them, and a margin from the frame's edge: *stretch* divides the space between the margins, and *start*, *center*, and *end* keep each band's width (a row's height) and place the block at that side (center ignores the margin). Each guide has its own color (default translucent red) and can be shown or hidden.
- The canvas overlay draws the visible guides of visible frames (with every ancestor visible), cut off by any ancestor that clips its content and by the edges of the canvas: columns and rows as filled bands, a grid as lines 1 screen point wide at every zoom. A grid whose lines would sit closer than 4 screen points is not drawn. Guides never appear in snapshots, thumbnails, or prototype playback.
- The properties panel's **Layout Guides** section of a selected frame lists its guides: **+** in the title row adds a 10-point grid; each row has the guide's type icon, a summary (*Grid 10*, *Columns 5*, *Rows 5*) that opens a popover to change its type, numbers, and color, an eye button to show or hide it, and **−** to remove it. Each change is one undo step (dragging in the color picker counts as one change).

**Creating**

- A toolbar floating at the bottom center of the canvas switches tools: Move V, Hand H, Frame F, Rectangle R, Ellipse O, Text T, Annotate C (see *Annotations* below). A creation tool drags out a size on the canvas (at least 1×1, so a straight-line drag still creates a visible layer), and a single click uses the default size (auto width and height for text); if the start point is inside a top-level frame, the new layer goes into that frame. After creating, the tool returns to Move. The toolbar stays centered in the canvas area as the side panels open and close and does not move with pan or zoom; clicks, drags, and scrolling on it do not reach the canvas.
- The bottom toolbar or Canvas › Insert Image… (画布 › 插入图片…, ⇧⌘I) inserts a PNG, JPEG, or SVG: when a frame is selected it goes into that frame, otherwise it is placed at the center of the viewport. A bitmap starts at half its pixel size, an SVG at its declared width and height (its `viewBox` size when it declares neither). An SVG keeps its source in the document and is rasterized again when the zoom settles or the layer grows, so it stays sharp; like other bitmaps on the canvas, its longest side is capped at 8192 pixels. The inspector's replace-image button accepts the same formats.
- An icon layer shows one icon from a built-in icon library (`sf`, `material-outlined`, `material-rounded`, `material-sharp`, `weui`, `lucide`), named `<library>/<name>`. It is drawn aspect-fit and centered in the layer, tinted with the icon color, and drawn again when the zoom settles or the layer grows, so it stays sharp; snapshots show it. SF Symbols are drawn by the system and the other libraries come from SVG data bundled with the App. A layer whose icon this Mac does not have (for example an SF Symbol from a newer macOS) draws a gray box with a diagonal line. Icon layers are selected, moved, resized, and laid out like other layers; a person inserts them with the icon picker and an Agent with `design_search_icons` and `design_create_node`.
- The bottom toolbar's *Insert Icon* (插入图标) button opens the icon picker in a popover: a segmented control switches between SF Symbols, Material Symbols, WeUI, and Lucide (Material Symbols adds a style menu: *Outlined*, *Rounded*, *Sharp*), the search field has focus, and Esc closes the popover. An empty search lists the whole library sorted by name (for SF Symbols, the localized variants such as `0.circle.ar` or `character.ja` come after the base names); otherwise the library's icons matching the query by name or keyword, best matches first, and *No Icons* when none match. The grid draws only the cells in view, in the label color, and shows an icon's name on hover; SF Symbols shows a line saying they may be used only in designs for Apple platforms. Clicking an icon inserts a 24 × 24 black icon layer named after the icon, placed as Insert Image places an image (into the selected frame at its top-left corner, otherwise centered in the viewport), selects it, and closes the popover; the insert is one undoable edit.
- Canvas › Save Version Snapshot (画布 › 保存版本快照, ⌥⌘S), or *Save Version Snapshot* in the *Version Snapshots* section of a frame's properties, saves a version snapshot of the one selected frame: the frame rendered at scale 2 into a read-only top-level image layer named "<frame name> Snapshot", the frame's size, placed 40 pt to the right of the frame (of its top-level frame, for a nested frame) and of its earlier snapshots, top-aligned with the frame, and selected; the picture's longest side is capped at 8192 pixels. *Replace Image…* is not offered for a snapshot. It is one undoable edit; with anything other than one frame selected, an alert asks for one. The frame's *Version Snapshots* section lists its snapshots by time (and note), and choosing one selects it and zooms to it. A snapshot's *Version Snapshot* section shows its frame (*Deleted* once the frame is gone), when it was saved, and a note committed on Return; *Overlay on Frame* moves it onto the frame at 50% opacity, where the opacity slider adjusts the overlay, and *Place Beside Frame* puts it back to the right at full opacity, each one undoable edit. A snapshot is otherwise an ordinary image layer: it is moved, resized, and deleted like one, and editing the frame never changes it.

**Annotations**

- An annotation is a plain-text note pinned to a point inside a layer, with a thread of replies; it is saved in the project file. Its marker is a round speech bubble whose pointed bottom-left corner sits on the point, showing how many messages the thread holds (yellow; the expanded one takes the accent color). Markers are drawn above everything else on the canvas, but they are not layers: they are not in the layers panel and not in snapshots.
- The Annotate tool (批注, C) in the bottom toolbar pins a new annotation: clicking a layer opens an empty thread at that point, on the deepest layer under the pointer whatever the selection; clicking empty canvas does nothing. The tool returns to Move after the click. The note is added only when its text is submitted (⌘Return or *Add*; Return starts a new line); collapsing it before then adds nothing.
- Pressing a marker, with any tool, expands its thread in a popover beside it; pressing the same marker again, pressing anywhere else on the canvas, or Esc collapses it (on the canvas, Esc collapses the thread before it would select the parent layer); a double-click counts as one press. Hiding or deleting the layer, undoing the note, or opening another file collapses it too. Pressing a marker never selects, moves, or creates layers, and dragging from it does nothing. Panning (Space, the Hand tool, the middle button) goes through markers and keeps the thread open; the popover follows its marker as the canvas pans and zooms.
- The thread lists the note and its replies with their author (*You* or *Agent*). Each message has *Edit* and delete buttons (deleting the first message deletes the whole annotation); the field at the bottom adds a reply. Adding, replying, editing, and deleting are each one undo step shared with layer edits.
- A marker follows its layer when the layer moves or is reparented, stays inside the layer when it shrinks, and is hidden while the layer or one of its ancestors is hidden. Deleting a layer deletes the annotations on it and its descendants in the same undo step. See [ADR 0011](adr/0011-annotations-in-the-design-document.md).

**Navigation**

- Scroll wheel or trackpad scrolling, Space + drag, middle-mouse drag, or dragging with the Hand tool pans the canvas. The cursor turns into a hand as soon as Space is pressed, and reverts on release.
- ⌘ / ⌃ + scroll wheel, or trackpad pinch, zooms anchored at the pointer, within 5%–400%.
- The window toolbar provides zoom out, the zoom percentage (click to return to 100%), zoom in, Fit All, and Play Prototype (see "Prototype" below). Menu shortcuts: ⌘+ zoom in, ⌘− zoom out, ⌘1 100%, ⌘0 Fit All.
- When the canvas has focus: Shift+1 fits all, Shift+2 zooms to the selection, Shift+0 returns to 100%. Double-clicking a top-level frame's name label zooms to focus on that frame. These transitions use a 200ms animation, and new input interrupts them immediately; with *Reduce motion* on in System Settings › Accessibility › Display they jump straight to the end (see [Accessibility](accessibility.md)).

**Undo**

- ⌘Z / ⇧⌘Z undo and redo changes to the design document; human and Agent changes share one history. When a text field has focus, these go to the text field. Creating or opening a file clears the history.

## Panels

- **Layers panel** (left sidebar): a hierarchy tree with upper layers first. Pressing a row selects it at once, without waiting for the mouse button to come up; ⌘-click adds or removes, Shift-click adds; double-click to rename. Hovering a row tints it and outlines its layer on the canvas, and hovering a layer on the canvas tints its row; the eye and lock buttons toggle visibility and locking; the context menu can move a layer up or down one level, bring it to the front or send it to the back, zoom to the layer, or delete it.
- **Inspector** (right side, ⌥⌘I shows or hides it) has three tabs along its top: Design (设计), Prototype (原型), and Chat (对话). The Design and Prototype tabs start with the selected layer's header: its type badge, its name (editable; Return renames), its type, and a show/hide button. Below it, sections are separated by thin dividers, with 16 pt side margins and 28 pt input boxes.
  - **Design tab**: *Position and Size* puts X and Y on one row and W and H on the next (X and Y are unavailable inside an auto layout frame; W and H for a group). W and H carry a sizing chip (*Fixed*, *Hug*, *Fill*) that opens the menu Fixed / Hug contents / Fill container; it appears for a layer in an auto layout frame, an auto layout frame, or a text layer, and never for a group, whose size always equals its children. Typing a W or H sets that axis to Fixed. *Auto Layout* (frames only) has *Remove* in its title row, or a `+` that adds a vertical auto layout with 8 pt gap; then the direction (*Vertical* / *Horizontal*), the alignment grid, *Gap*, *Space between*, *Stretch*, the four paddings on one row (top, right, bottom, left), and *Clip content*, which is shown for every frame. *Appearance* has opacity (as a percentage) and corner radius side by side; dragging the opacity icon sideways changes it. *Fill* (*Background* for a text layer) and *Stroke* show a swatch that opens the color picker, the six-digit hex, which can be typed (with or without `#`; eight digits also set the alpha), the opacity, and a remove button; *Stroke* adds its weight. A layer without a fill or stroke shows that section folded to its title with a `+` that adds white fill or a 1 pt black stroke. *Effects* (every layer type but group) is folded to its title while empty; its `+` menu adds a Drop Shadow, Inner Shadow, Layer Blur, Background Blur, or (for frames, rectangles, and ellipses) Noise, Texture, or Glass with default settings (Glass is left out while the layer has a Glass or a Background Blur, and Background Blur while it has a Glass), shown expanded; Texture first asks for a PNG, JPEG, or SVG, and cancelling adds nothing (switching a row's type to Texture asks the same way). Each effect is one row, the frontmost at the top as in the layers panel (effects are drawn bottom row first): the chevron shows or hides its settings (a shadow's color, X/Y offset, blur, and spread, which text and icon layers do not offer; a blur's radius; noise's color, grain *Size*, *Density* as a percentage, and *Seed*; a texture's tile *Size*, opacity, *Blend*, and *Replace Image…*; glass's *Tint*, *Blur*, *Saturation*, and *Highlight* as a percentage), the type menu switches its type (a shadow keeps its settings when switched to the other shadow type), the eye hides it without removing it, and the remove button removes it; *Move Up* (forward) and *Move Down* (backward) in the row's context menu reorder it. The canvas, snapshots, and the prototype window draw effects alike; a background blur blurs only the layers under it in the same parent. Then come the text, image, and icon sections: the icon's name and color (*Replace Icon…* opens the icon picker on the icon's library, scrolled to the current icon, and swaps the icon in one undoable edit, keeping its position, size, and color; a layer still named after the old icon is renamed after the new one, while a name the person chose stays). With multiple layers selected, the Design tab changes the opacity of all of them at once.
  - **Alignment grid**: the 3×3 grid shows a frame's layout as positions in the frame — rows top to bottom, columns left to right — so a click sets the main-axis and cross-axis alignment together (in a horizontal layout the columns are the main axis, in a vertical one the rows). *Space between* holds the main axis and *Stretch* the cross axis: while one is on, the grid highlights a whole line and a click sets only the other axis; with both on, the grid is unavailable. Turning *Space between* off returns the main axis to start, and turning *Stretch* off returns the cross axis to start.
  - **Prototype tab**: the selected layer's interaction, hover and pressed states, scrolling, and animation (see "Prototype" below). It needs a single selected layer.
  - Every change in either tab is one undo step in the shared history; the edits of a continuous change, such as dragging in the color picker or the opacity icon, are merged into one step as long as they follow each other within 1.5 s. The text section's *Font* menu lists *System Default* (no `fontFamily`) followed by the font families installed on the system and those in the font library, sorted by name; a layer whose `fontFamily` is not available on this Mac shows it marked *(missing)* and is drawn with the system font. Choosing a family is one undoable edit. *Import Font…* copies one or more `.ttf`, `.otf`, or `.ttc` files into the font library (`~/Library/Application Support/fudehand/Fonts`), replacing a file of the same name, and registers them for the App only: they become available at once, text layers already set to their family are drawn with it, and the App registers the whole library again at each launch. A file that is not a font is reported and not copied. The Chat (对话) tab is the Agent chat panel (⇧⌘A); see "Chat panel" below.
- The appearance menu in the top right chooses Follow System, Light, or Dark.

### Chat panel

- **Conversations**: the header shows the open conversations as conversation tabs, then *New conversation*, the *Conversation history* menu, and *Model settings*. A tab shows the conversation's name (the start of its first message, or *New conversation*), a dot while its reply is running, and a close button; the tabs share the header's width, shortening their names, and scroll sideways once they cannot get any narrower. Each conversation has its own messages, context, model, and Agent harness process: *New conversation* opens an empty one with the current conversation's model (or selects a tab that is already empty), and a reply keeps running while another tab is shown. Stopping, regenerating, editing, and choosing a model act on the selected conversation only. Closing a tab stops its reply and keeps the conversation in the history; closing the last tab leaves an empty conversation. Conversations belong to the design document's project file, found by the file's canonical path: opening a document shows its conversations and no other document's, with the conversation tabs that were open restored in order — messages, tool calls and results, the selected tab, and each conversation's provider and model — so they are as they were after quitting and reopening the App. A closed tab does not come back as a tab. A reply that was running at quit is kept as stopped, not resumed. A document that has no file yet keeps its conversations while it is open: the first save takes them to the file, *Save As* copies them to the new file, and they are dropped when the document is replaced or the App quits without a save. A file that is moved or renamed starts without conversations. When the document is replaced while a reply is running (the Agent creating or opening a document, for example), that conversation stays open and its reply continues: from then on it is saved with the new document, and the old document keeps it as it was at that moment; the other conversations stay with the old document. Conversations are saved as JSON under `~/Library/Application Support/fudehand/chats`, in one directory per project file named by a hash of its path (the 50 most recent per document are kept), when a message is sent, when a reply ends, and when a conversation's model changes; never in the project file, and without the API key or base URL. Saved data that cannot be read is skipped, down to a single empty conversation. *Conversation history* lists the shown document's conversations; choosing one selects its tab when it is open; otherwise it opens in place of an empty current conversation, or in a new tab, with the model it was saved with. *Delete This Conversation* removes the selected conversation from the history and closes its tab; it is unavailable while that conversation is replying. Saving a provider's API key or base URL in *Model settings* (or through an Agent's `settings_*` tool) restarts the harness of every conversation using that provider with the new value; a conversation whose reply is running finishes that reply first, and its next message starts the new harness. Quitting the App ends every harness.
- **Transcript**: replies stream in and render Markdown (headings, lists, inline code, links, quotes, code blocks with *Copy code*; long code lines scroll sideways). A tool call is one card: a running, succeeded, or failed icon and a title naming the action and what it acts on, opening to show the arguments and the result. Two or more consecutive calls fold into "Ran N steps", open while they are the newest thing happening.
- **Questions**: when a request is ambiguous or lacks information that would change the result, the Agent can pause its reply and ask one question, shown as a question card: the question, an optional line on why it asks, 2–4 options (the first is the Agent's recommendation and is marked *Recommended*), a field for another answer, and *Skip, let AI decide*. Clicking an option, sending another answer (from the card or from the chat input), or skipping folds the card down to the question and the answer, and the reply continues. No tool call runs while the question waits; the transcript shows *Waiting for your answer* and the conversation's tab shows a hollow orange ring instead of the dot, while other conversations keep working. The stop button cancels the question and ends the reply. A question still unanswered when the App quits, its tab closes, or its harness restarts stays open in the saved conversation: answering it later starts a new harness with the conversation so far and continues from the answer. Editing or regenerating the last message moves on from an open question.
- **Scrolling**: the transcript follows new text while the view is at the bottom. Scrolling up stops the following and shows *Scroll to bottom*; sending a message returns to the bottom.
- **Input**: grows up to 8 lines; Return sends, Shift-Return starts a new line, and a draft can be typed while a reply is running. Below it are the model menu and the send or stop button. The model menu's button shows the provider and model; the menu has one section per model provider. A provider with an API key lists its models as last fetched (more than 8 fold into an *All N Models* submenu, which keeps the default and the selected model visible), and choosing one switches the provider and model in one step. A provider without a key shows *Add API Key…*, which opens *Model settings* on that provider. *Reload Model List* reloads the provider in use, and *Model Settings…* opens the sheet; the menu is unavailable while the selected conversation's reply is running. The draft in the input is kept when another tab is selected. Stopping keeps the text received so far.
- **Next-message prediction**: after a reply ends normally, the Agent harness asks the model for the message the user is most likely to send next, and the empty input shows it as its placeholder with a *Tab* keycap beside it. Tab in the focused, empty input puts the prediction in the input, where it can be changed before sending; anywhere else Tab keeps its usual behavior. It is not offered while the last message is being edited. Typed text is never replaced: the prediction is only a placeholder, shown again if the input is emptied, and dropped when the next message is sent or the last one is taken back for editing. Each conversation has its own prediction. The prediction is a separate, short model request (the last few user and assistant texts, no tools) that is not written into the conversation, the harness's history, or a reply's token usage; when it fails, times out, or no API key is set, the placeholder stays *Message* and nothing is reported. A stopped or failed reply gets no prediction.
- **Slash commands**: typing `/` as the first character of the input opens the command menu above it; further letters narrow it to the commands whose name starts with them. ↑ and ↓ move the highlight, Return or a click runs the highlighted command, and Esc closes the menu until the text changes or Return shows it again. A message that does not start with `/` never opens it. A command is never sent to the model: Return on a name that is no command shows *Unknown command* under the input and leaves the text in place. The commands:
  - `/plan` switches the conversation to **plan mode**. The Agent harness then offers the model only the tools that read the design document (`design_get_state`, `design_get_document`, `design_get_node`, `design_snapshot`) and asking the user a question, and refuses any other call, and the model replies with the steps it would take. While that plan is the newest reply, *Run Plan* above the input leaves plan mode and sends *Carry out the plan.* as an ordinary message, with the context tags like any other; replying instead keeps plan mode on and asks for a changed plan.
  - `/goal` switches to **goal mode** for the next message, which is the goal. The model keeps calling tools — up to 64 rounds instead of an ordinary reply's 16 — until it reports the goal done with a summary, which is shown as the reply's last text; a report without a summary is refused and asked for again, and tools called after the report in the same round are not run. A round without tool calls, such as a progress note, gets a reminder to go on, up to three in a row; a fourth such round in a row ends the goal as it stands. *Stop replying* interrupts it like any reply, and nothing further runs. Goal mode ends with that reply, however it ends; *Regenerate* on that reply works on the goal again.
  - `/new` is *New conversation*; `/clear` empties the selected conversation in place, stopping its reply and removing it from the history; `/compact` compacts it (see *Compacting*), and is unavailable while a reply is running; `/model` lists the models of the model menu in the command menu, narrowed by what is typed after it, with *Model Settings…* last. Choosing a model is unavailable while a reply is running, as in the model menu.
  - Text typed after `/plan` or `/goal` is sent as the first message in that mode.
- **Mode tag**: while a conversation is in plan or goal mode, a tag above the input names the mode and its button leaves it; the input's placeholder says what to type, in place of the next-message prediction, which is not made for a plan. The mode belongs to the conversation, is not saved with it — except that a question a plan or goal reply was waiting on when the App quit or the tab closed restores that mode, and its answer continues the reply in it — and applies to the messages sent while it is on: a command run during a reply takes effect with the next message.
- **Model settings**: the sheet lists every model provider with a filled mark when it has an API key and a hollow one when it does not, its model (or *No API key*), and an *In use* tag on the provider the chat will use; it opens with the chat's provider selected. The detail pane edits the selected provider's API key (*Test*, *Replace*, *Remove*), base URL, and model, and *Use for Chat* makes that provider the one the chat uses. Every edit, including *Remove*, is held per provider and takes effect only on *Save*; *Cancel* discards them all. *Test* fetches the provider's model list with the entered key, or the saved key when none was typed; a pass caches the list for the model menus, and a failure shows the message and hides *Use for Chat* but does not block saving. Leaving the key field after typing a key runs the test automatically. If, after saving, the provider in use has no key and another provider has one, the chat switches to the first provider with a key. Opening the sheet or selecting a provider does not read the Keychain; only *Test* with a saved key does.
- **Context tags**: the layers selected on the canvas appear above the input; each can be removed, and comes back when the layer is selected again. The remaining ones are sent with the message.
- **Message actions**: *Copy message* on every assistant reply (under the pointer; always shown on the newest one), *Regenerate* on the newest reply, and *Edit and resend* on the last user message, which copies it into the input; sending the changed text replaces the message and its reply, and cancelling leaves the conversation as it was. Neither undoes the edits the replaced reply made to the design document: use Undo first to have them made again from scratch.
- **Token usage**: next to a reply's actions, the tokens the model API reported for the whole reply — input plus output, added up over every request the reply made, each of which resends the system prompt, the tool definitions, and the history so far. The tooltip splits it into input, the part of the input read from the provider's cache, and output. A stopped or failed reply counts the requests that completed. Nothing is shown when the provider reports no usage; the number is never estimated.
- **Context ring**: left of the send button, a ring fills with the share of the selected model's context window that the conversation takes up. The amount is what the model API reported for the last request of the newest reply (input plus output); it is saved with the conversation, and nothing is estimated. The window comes from the provider's model list, so it follows the model: choosing another model redraws the ring against that model's window at once. The ring turns orange from 75 % and red from 90 %; hovering shows the tokens used, the window, and the percentage, and near the limit suggests `/compact`. A model whose window is not known (a list fetched before windows were recorded, a custom endpoint, a model the list does not name) shows an empty ring and the tokens used; *Reload Model List* looks it up.
- **Compacting**: the `/compact` slash command compacts the selected conversation: the Agent harness asks the model for a summary of the conversation and from then on the model sees that summary instead of the earlier messages. The transcript keeps every message and gains a *Context compacted* row that opens to show the summary; the ring drops to the summary's size until the next reply reports the real amount (to empty when the model API reported no usage for the summary). While it runs the panel shows *Compacting context…* and the stop button stops it. A stop or a failure leaves the messages and the model's context as they were; a stop adds a *Compacting stopped* notice and a failure an error row. The compaction is saved with the conversation, so a reopened conversation continues from the summary. Regenerating or editing a message sent before the compaction takes the compaction back with it: the model is given the messages up to that point again. Nothing is compacted automatically, and `/compact` does nothing in a conversation with no messages since the last compaction.
- The Agent harness keeps the full history, including tool results, while it runs. A new harness — after a relaunch, a model change, or switching, regenerating, or editing — is given the conversation's user and assistant texts only, starting at the summary when the conversation was compacted.

## Prototype

Any layer can have one click interaction that turns the design document into a clickable prototype (see [ADR 0007](adr/0007-prototype-interactions.md)); frames can scroll, layers can have hover and pressed states, and interactions can open overlays and toggle layers within a screen ([ADR 0009](adr/0009-in-screen-prototype-interactions.md)).

- **Editing**: the Prototype (原型) section of the inspector's Prototype tab. *Add Interaction* gives the selected layer *On click → Navigate to* the first top-level frame other than the one holding the layer (or *Back* when there is none). *Action* switches between *Navigate to* (跳转到) a top-level frame, *Back* (返回), *Open Overlay* (打开弹层), *Close Overlay* (关闭弹层), and *Toggle Visibility* (切换显示) (see below); *Destination* lists the top-level frames, the one holding the layer last, and shows *Missing frame* (画框不存在) when the frame it pointed to was deleted. *Transition* is None, Dissolve, Push Left / Right / Up / Down, or Bottom Sheet; when it is not None, *Duration (s)* (0–10, default 0.3) and *Easing* (Linear, Ease In, Ease Out — the default — or Ease In and Out) appear. *Remove Interaction* takes it off. Every change is one undo step in the shared history, and the Agent sets the same field through `design_create_node` / `design_update_node`.
- **Transitions**: a push names the direction the content travels — Push Left brings the destination in from the right while the current frame leaves to the left. Bottom Sheet slides the destination up from the bottom over the current frame. Back plays the transition that arrived at the current frame in reverse (a push slides back, a dissolve fades the current frame out, a sheet slides down).
- **Playing**: Canvas › Play Prototype (画布 › 播放原型, ⌥⌘↩) or the ▶ button in the window toolbar opens the prototype window, starting from the top-level frame holding the selection, otherwise the first top-level frame; with no top-level frame it says to add one. Playing again restarts from the current selection. The window is also listed in the Window menu; opened from there it shows the last playback, or says to choose Play Prototype when nothing has been played.
- **Prototype window**: a separate window, sized to the frame on show (frames larger than the screen are scaled down to fit), titled with the frame's name. It resizes when it moves to a frame of another size. A click — pressed and released over the same layer — goes to the layer under the pointer — or, when that layer has no interaction, to its nearest ancestor that has one, up to the frame itself; hidden layers and everything in them never answer, and content clipped away by a frame cannot be clicked. The pointer becomes a pointing hand over a layer that answers. While a transition plays, clicks are ignored. An interaction whose destination is missing or not a top-level frame does nothing, and *Back* with no earlier frame does nothing; frames deleted since they were shown are skipped on the way back. Esc or ⌘W closes the window and returns to editing; the editing canvas, its selection, and its viewport are never changed by playback.
- **Scrolling**: a frame's *Scrolling* setting (None, Vertical, Horizontal; in the Prototype section) lets its content scroll in the prototype window when it overflows: the trackpad or the mouse wheel scroll the innermost scrolling frame under the pointer that can still move that way, otherwise the next one out; a mouse wheel's vertical movement scrolls a horizontal frame, while a trackpad's vertical swipe over it scrolls the frame around it. The range runs from the start of the content to the far edge of its visible children (plus the auto layout padding after them), and scrolling stops at either end; the trackpad's momentum carries on after a flick. A direct child with *Fix position when scrolling* does not move and is drawn above the scrolled content, in its own stacking order. Going to a frame, or opening it as an overlay, starts it at the top; *Back* returns to a frame where it was scrolled. Scrolling does not clip by itself: a scrolling frame with *Clip content* off lets its scrolled content show (and be clicked) beyond its edges. The editing canvas shows frames unscrolled, as before.
- **States**: *Add Hover State* and *Add Pressed State* (Prototype section) give a layer a look for *While hovered* and *While pressed*: a fill (*Add Fill*) and an opacity that replace the layer's own, each change eased over 0.15 s. The layer showing states is the topmost layer under the pointer that has states, otherwise its nearest ancestor that has them, found by the same hit rules as clicks. It is hovered while the pointer is over it and pressed while the button is held after going down over it and the pointer stays over it; pressed applies on top of hover.
- **Overlays**: *Open Overlay* shows a top-level frame over the frame on show, at *Position* Center, Bottom (centered horizontally), or Below Layer (its top-left corner at the bottom-left of the clicked layer), kept inside the frame on show. *Background* draws a color over the whole frame below (default black at 40% when added in the panel; none when the Agent omits it). *Close when clicking outside* (default on) closes it on a click outside it; when off, such clicks do nothing. The transition brings it in — a push from the edge it names, Bottom Sheet from the bottom, Dissolve fading — while the background fades; closing plays it in reverse, and the overlay stops taking input as soon as it starts closing. Overlays stack; only the topmost takes clicks, hover, and scrolling. *Close Overlay* and *Back* close the topmost overlay; *Navigate to* from an overlay closes every overlay first and then moves to its frame. A frame already on show cannot be opened as an overlay over itself. An overlay shows its layers as designed: their animations and text sequences do not play.
- **Toggle Visibility**: shows the hidden and hides the shown among the chosen layers (*Add Layer* lists the other layers of the same top-level frame). The result lasts until playback restarts; the design document is never changed, so playing again starts from the layers' own visibility. Layers deleted since are skipped.
- **Animation**: the Animation (动画) section below Prototype, in the Prototype tab. *Add Animation* adds a Fade In; *Type* chooses an entrance (Fade In, Slide In, Scale In) or a loop (Spin, Pulse, Shimmer), resetting the other fields to that type's defaults but keeping the delay. Slide In adds *From* (Left, Right, Top, Bottom — default Bottom) and *Distance* (default 40 pt); Pulse adds *Pulses* (Scale or Opacity). *Duration (s)* (one cycle for a loop; up to 60), *Delay (s)* (up to 60), *Easing*, and *Repeat forever* — or *Times* (1–1000) when it is off — apply to all types. Defaults: entrances 0.3 s, Ease Out, once; Spin and Pulse 1 s, Shimmer 1.5 s, forever, Linear (Pulse: Ease In and Out). Slide In and Scale In (from 80 %) also fade in; Spin turns clockwise about the layer's center; Pulse scales to 110 % or fades to 40 % and back; Shimmer sweeps a see-through band across the layer from left to right, including its children. A text layer's Text section has *Add Text Sequence*: items one per line (a whole-number text from 1 to 999 starts as a countdown to 0, anything else as its own text), *Interval (s)* (0.05–3600, default 1), *Loop*, and *Remove Text Sequence*. Every change is one undo step; the Agent sets `animation` and `text.sequence` through `design_create_node` / `design_update_node` (see [ADR 0008](adr/0008-layer-animations.md)).
- **When animations play**: in the prototype window, every visible layer of a frame starts its animation, and every visible text sequence its first item, when the frame appears: at the start of playback, and after the transition that brings the frame in (until then entrance layers wait in their starting state, so they are hidden during the transition). Hidden layers and everything in them do not animate. A loop keeps going while its frame is on show and stops when the frame has left; coming back to a frame starts it all over. Edits during playback re-render the frame (its layout and texts) without restarting its animations; a change to an animation itself, or to the opacity or size it starts from, plays the next time the frame appears. A text sequence shows each item with the layer's own text style and auto-size rules, and an auto layout parent re-flows around it; a sequence that does not loop stays on its last item.
- **Preview**: *Preview* in the Animation section (also shown, next to *Add Animation*, for a layer holding a text sequence) opens a popover that plays the selected layer and its children — scaled down when larger than the box — with *Replay*; changes made while it is open play again at once. Previewing does not play the prototype.
- **Still where editing**: the editing canvas, `design_snapshot`, and thumbnails never animate; they show each layer's static state and a text layer's own text.
- **Edits during playback**: the prototype window follows the design document: edits by people or the Agent show up when they are committed (a drag on the canvas shows at its end). If the frame on show is deleted, the window says so and offers *Play from the Start*.

## Performance Troubleshooting

Launch the App with `FUDEHAND_FRAME_LOG=1` and it prints one line per second to stderr, `[frame] hitches=N frames=M`, for comparing dropped frames while panning and zooming.

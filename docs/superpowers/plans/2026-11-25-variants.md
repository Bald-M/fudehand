# Variants and Component Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Component sets, variants, variant properties, and switching an instance between variants (step 2 of #256), plus two *Reset Overrides* fixes left by step 1.

**Architecture:** Two new optional fields in step 1's `ComponentFields` box (`componentSet` on a set frame, `variant` on its main-component children). Pure editing functions in a new `ComponentVariants.swift` (`FudehandCore`); structure rules join step 1's in `DesignDocument.insert/delete/move` and `LayerClipboard`; switching rebuilds the instance with step 1's `makeInstance` and re-uses matched layers' ids by name path. Store methods back both the UI and five new Agent tools.

**Tech Stack:** Swift 6 toolchain (Swift 5 mode), SwiftUI + AppKit, `FudehandCore`/`FudehandApp`, Node MCP tools, Vitest, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-25-variants-design.md` (builds on `docs/superpowers/specs/2026-11-24-components-design.md` and ADR 0014)

## Review Focus

- **Switching keeps what still matches:** an overridden title text survives a Default → Disabled switch when both variants have a layer named Title — `switchKeepsOverridesOnMatchedLayers` (Task 3).
- **Duplicate values after a property removal:** removing *Size* from a set whose variants differ only by size is refused, document unchanged — `removingPropertyThatMakesDuplicatesIsRefused` (Task 2).
- **Undo of a switch:** restores the old variant, ids, overrides, annotations exactly — `switchIsOneUndoStep` (Task 3).
- **Instance of a set:** inserting a set id makes an instance of its first variant, and reordering variants changes only later inserts — `instanceOfSetUsesFirstVariant` (Task 4).
- **Pasting into a set:** a plain rectangle pasted with a set selected does not go into the set (it lands at top level), and a variant duplicated inside a set becomes a new variant with unique values — `pasteAndDuplicateAroundSets` (Task 2).

- Produces (all `throws`, mutate `inout DesignDocument`, English `DesignError`s naming layers):
  ```swift
  public enum ComponentVariants {
      public static func combine(_ ids: [String], in document: inout DesignDocument, propertyName: String) throws -> String  // new set id
      public static func setProperties(_ set: String, _ properties: [String], rename: [String: String], defaultValue: String, in document: inout DesignDocument) throws
      public static func setValues(_ variant: String, _ values: [String: String], in document: inout DesignDocument) throws
      public static func addVariant(from id: String, in document: inout DesignDocument) throws -> String  // id = variant or set
      public static func set(of variant: String, in document: DesignDocument) -> String?
      public static func uniqueValue(_ base: String, among: Set<String>) -> String  // "X", "X 2", "X 3"
  }
  ```
  `combine`: spec "Creating a component set" (same parent, ≥1 main component not in a set; frame at union + 16 padding, keep canvas positions, named after the first; property values = names made unique). `addVariant`: copy of the variant (fresh ids, `component` kept, new main component), inserted just after it, placed 16 pt below it, first property value made unique, set grows to include it. Insert/move refuse moving into or out of a set (`Layer <set> is a component set; use Combine as Variants or Add Variant`) except through these functions; reorder within a set allowed; deleting a set or variant uses step 1's detaching delete.
